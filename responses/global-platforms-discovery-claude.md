- **Relevance:** 5

- **Technical Architecture (4/5):** Modular Python/C++ pipeline with CityJSON and CityGML data models, designed for automated city model generation from point clouds and GIS data, with containerised deployment via Docker ([GitHub](https://github.com/dtcc-platform)).
- **Openness & Licensing (5/5):** Apache-2.0 licensed across all public repositories; fully self-hostable with open data formats (CityJSON, CityGML, OGC-compatible) and no SaaS dependency ([GitHub](https://github.com/dtcc-platform)).
- **City-Scale Capability (4/5):** Covers buildings, terrain, and urban infrastructure at city scale with automated generation from open geodata sources; energy and mobility domains are partially addressed through research extensions ([DTCC Documentation](https://dtcc.chalmers.se/research/)).
- **Maturity & Adoption (3/5):** Research-grade with active development; known deployments in Gothenburg and other Swedish municipalities; community activity centred on Chalmers research group with open GitHub contributions ([GitHub pulse](https://github.com/dtcc-platform)).
- **Integration Posture (3/5):** Python API and CLI tools; outputs standard CityJSON/CityGML consumable by downstream tools; limited plugin ecosystem beyond core pipeline ([GitHub](https://github.com/dtcc-platform/dtcc-builder)).
- **Governance (4/5):** Governed by Chalmers University with academic–municipal partnerships; publicly funded through Swedish research grants; open contribution model on GitHub ([About](https://dtcc.chalmers.se/about/)).
- **Visualization (3/5):** Integrated 3D viewer via dtcc-viewer; useful for inspection but not a primary purpose-built rendering engine ([GitHub dtcc-viewer](https://github.com/dtcc-platform/dtcc-viewer)).
- **Data Management (4/5):** Automated ingestion of point clouds, OSM, and cadastral GIS data into a semantic CityJSON city model with versioned outputs ([dtcc-builder README](https://github.com/dtcc-platform/dtcc-builder)).
- **Simulation (3/5):** Supports shadow, wind, and noise simulation modules as research extensions; limited multi-domain scenario tooling at this stage ([Research](https://dtcc.chalmers.se/research/)).
- **IoT Sensing (2/5):** No native real-time IoT ingestion; designed for batch geodata processing rather than live sensor streams.
- **Standards (4/5):** Native CityGML and CityJSON support; OGC-compatible data outputs; partial IFC ingestion under development ([GitHub](https://github.com/dtcc-platform)).
- **Infrastructure (3/5):** Covers buildings and road network geometry from GIS; limited BIM lifecycle management or civil engineering asset tracking.

- **Integration Posture (5/5):** OGC WFS 2.0, WMS 1.3, WCS 2.0, WMTS, WPS, and CSW; REST API; extensive plugin ecosystem; integrates with QGIS, ArcGIS, 3DCityDB, and virtually all GIS tools ([GeoServer docs](https://docs.geoserver.org)).
- **Governance (4/5):** OSGeo Foundation governance; community-driven development with diverse contributor base; transparent roadmap via GitHub ([OSGeo](https://www.osgeo.org/projects/geoserver/)).
- **Visualization (2/5):** Web map preview capability; not a 3D or UDT-grade visualisation tool; 2D map tiles served via WMS/WMTS.
- **Data Management (5/5):** Purpose-built for geospatial data serving and management; multi-source ingestion, styling, transformation, and OGC-standard publication are core functions.
- **Simulation (1/5):** No simulation capability; geospatial data publication only.
- **IoT Sensing (1/5):** No native IoT integration; static or near-static geospatial data serving.
- **Standards (5/5):** Primary purpose includes implementing OGC WFS/WMS/WCS/WPS standards; one of the reference implementations of multiple OGC standards; OSGeo governance role ([OGC reference](https://www.ogc.org)).
- **Infrastructure (2/5):** Can serve infrastructure geometry datasets; no BIM or lifecycle management role.
