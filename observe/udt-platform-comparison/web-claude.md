## Part 2 — Platform Profiles

### DTCC Platform

**Organization:** Digital Twin Cities Centre, Chalmers University of Technology
**Link:** [dtcc.chalmers.se](https://dtcc.chalmers.se)
**Description:** An open-source platform for creating and exploring digital twins of cities, with automated pipelines for generating 3D city models from raw geodata and running multi-domain urban simulations. Developed by a Vinnova-funded Swedish national competence centre with 35+ academic, municipal, and industry partners.
**Type:** Open-source research platform
**License:** MIT

#### Dimension Analysis

**Technical Architecture (4/5):** The DTCC Platform follows a fully modular multi-repository architecture under the [dtcc-platform GitHub organization](https://github.com/dtcc-platform), comprising **32 repositories** including dtcc (top-level orchestration), dtcc-core (data model and builders), dtcc-data (automated data downloading), dtcc-viewer (visualization), dtcc-sim (simulation), dtcc-solar (solar analysis), and dtcc-agent (AI agent for autonomous scenario analysis via MCP). The platform adopts [CityJSON as its primary data model](https://dtcc.chalmers.se/digital-twin-platform/), an OGC community standard encoding of the CityGML schema, with a rich Python object model covering City, Building, Terrain, PointCloud, Mesh, VolumeMesh, RoadNetwork, and LandUse classes. The architecture includes a [server-based REST API for running simulations](https://dtcc.chalmers.se/digital-twin-platform/) and uses PostGIS for geospatial data storage via the related Digital Twin City Viewer component. The platform is self-hostable and installable via `pip install dtcc`, primarily in Python with C++ for computational components, though it lacks cloud-native containerized deployment and does not yet expose OGC API-compliant service endpoints.

**Openness & Licensing (5/5):** All repositories under dtcc-platform are confirmed licensed under the **MIT License**, as stated consistently across [dtcc](https://github.com/dtcc-platform/dtcc), [dtcc-core](https://github.com/dtcc-platform/dtcc-core), [dtcc-builder](https://github.com/dtcc-platform/dtcc-builder), and all other packages — correcting the discovery baseline which claimed Apache-2.0. The MIT license is maximally permissive with no copyleft restrictions. The platform uses CityJSON (OGC standard) as its primary data format and ingests data from open sources including [Lantmäteriet (Swedish mapping authority) and OpenStreetMap](https://www.gim-international.com/content/article/modelling-and-simulating-cities-with-digital-twins). There is no SaaS dependency; the entire platform runs locally, and the [contribution process is fully open via GitHub Issues, Pull Requests, and Discussions](https://github.com/dtcc-platform/dtcc).

**City-Scale Capability (3/5):** The platform covers buildings, terrain, road networks, vegetation, and land use, with simulation modules for [wind comfort (CFD/RANS), air quality, street noise, solar irradiance, urban heat, crowd movement, and geotechnical analysis](https://www.gim-international.com/content/article/modelling-and-simulating-cities-with-digital-twins). Current building models are primarily at **LOD1** (polygonal prisms), with LOD2 roof reconstruction under development using ML segmentation. The platform has been demonstrated at [Gothenburg city scale](https://dtcc.chalmers.se/virtual-gothenburg-the-citys-digital-twin/) with demo data covering Helsingborg residential areas, but operational coverage remains limited to select Swedish municipalities rather than full multi-domain city-wide deployment.

**Maturity & Adoption (3/5):** The platform is at **version 0.9.6** with active development — the most recent commits on dtcc-core and dtcc-atlas dated [March 25, 2026](https://github.com/dtcc-platform), and dtcc-web updated March 26, 2026. GitHub activity shows low community traction with only **2 stars** on the main dtcc repo and **4 stars** on dtcc-ue-plugin. Named municipal partners include the [City of Gothenburg (Virtual Gothenburg Lab), Helsingborg, Lund, Höganäs, Linköping, and Ale](https://research.chalmers.se/en/project/9438), but deployments remain research-grade pilots rather than operational production systems. International research collaborations exist with [GATE Institute (Bulgaria) and Fraunhofer (Germany)](https://dtcc.chalmers.se/urban-environmental-comfort-design/).

**Integration Posture (3/5):** The platform provides a REST API for simulation invocation and uses CityJSON as an interoperable data format, enabling exchange with other CityGML-compatible tools. The modular Python package architecture allows individual components (viewer, sim, solar) to be used independently. However, no OGC API-compliant service endpoints were found in the documentation, there is no plugin ecosystem, and integration with external tools like Unreal Engine requires the dedicated [dtcc-ue-plugin](https://github.com/dtcc-platform/dtcc-ue-plugin). Web visualization options tested include [Mapbox, CesiumJS, and Babylon.js](https://www.gim-international.com/content/article/modelling-and-simulating-cities-with-digital-twins), but these remain loosely coupled rather than formally integrated.

**Governance (4/5):** DTCC is a **Vinnova-funded national competence centre** (Grant No. 2019-00041) hosted by Chalmers University of Technology, with Phase 2 (2025–2029) receiving [SEK 36 million from Vinnova](https://www.vinnova.se/en/p/digital-twin-cities-centre-phase-2/). The centre is directed by Professor Anders Logg (Computational Mathematics, Chalmers) and managed by [Chalmers Industriteknik for scientific coordination](https://chalmersindustriteknik.se/en/project/digital-twins-cities-centre/). A **consortium of 35+ partners** spanning academia, industry (AFRY, NCC, Ramboll, Tengbom), and public sector (City of Gothenburg, multiple municipalities) provides broad stakeholder input, with a Board providing strategic oversight. Additional funding included an [Epic MegaGrant for visualization work](https://www.gim-international.com/content/article/modelling-and-simulating-cities-with-digital-twins). External contributions are welcomed through the standard GitHub workflow of Issues and Pull Requests.

### Virtual Singapore

**Organization:** National Research Foundation (NRF) and Singapore Land Authority (SLA), Government of Singapore
**Link:** [nrf.gov.sg/programmes/virtual-singapore](https://www.nrf.gov.sg/programmes/virtual-singapore)
**Description:** A national-scale dynamic 3D city model and collaborative data platform covering all of Singapore, integrating over 200,000 LOD2 building models with terrain, vegetation, transport, and underground utilities for whole-of-government planning, simulation, and decision-making. Built on Dassault Systèmes' 3DEXPERIENCity platform with Bentley Systems reality capture tools.
**Type:** Proprietary government digital twin programme
**License:** Proprietary (government-owned, restricted access)

#### Dimension Analysis

**Technical Architecture (4/5):** Virtual Singapore is built on [Dassault Systèmes' 3DEXPERIENCity platform](https://www.3ds.com/newsroom/press-releases/dassault-systemes-and-national-research-foundation-collaborate-develop-virtual-singapore-platform), providing the core simulation and collaboration engine. The 3D mapping infrastructure uses [Bentley MicroStation for data capture, ContextCapture for 0.1-meter accurate reality meshes, and Bentley Map for CityGML data management atop Oracle Spatial](https://geospatialworld.net/prime/case-study/national-mapping/virtual-singapore-building-a-3d-empowered-smart-nation/). The platform adopts **CityGML 2.0** as its primary data standard, implementing [8 of 10 thematic modules](https://www.researchgate.net/publication/320569453_CITYGML_MODELLING_FOR_SINGAPORE_3D_NATIONAL_MAPPING) (Building, Relief, Vegetation, WaterBody, Transportation, CityFurniture, Bridge, Tunnel). The public-facing [OneMap3D](https://www.sla.gov.sg/news/press-release/sla-launches-onemap3d--and-signs-mous-with-ninja-van--kabam-and-propnex-to-further-the-use-of-onemap/) was built in-house by SLA using open-source 3D geospatial technology with Cesium as the rendering engine, delivering 3DTiles over the web.

**Openness & Licensing (1/5):** Virtual Singapore is a **proprietary government programme** with no open-source components. The core platform is [restricted to authorized users from government agencies and approved private entities](https://geospatialworld.net/prime/case-study/national-mapping/virtual-singapore-building-a-3d-empowered-smart-nation/), with functionality varying by user segment and subject to data confidentiality protocols. Public access is limited to [OneMap3D](https://www.geoworks.sg/onemap3d-developer-programme), which provides free web-based 3D viewing and a developer programme offering 3D building models in CityGML v2 format and 3DTiles APIs. The underlying Dassault 3DEXPERIENCity platform and Bentley tools are fully commercial software, and no source code or data processing pipelines are publicly available.

**City-Scale Capability (5/5):** This is the most comprehensive national-scale urban digital twin in operation, covering **all of Singapore** with **over 200,000 building models at LOD2** (explicit roof structures) generated from aerial imagery and point cloud data at [0.1–0.3 meter accuracy](https://venturebeat.com/technology/how-singapore-created-the-first-country-scale-digital-twin). Domain coverage spans buildings, relief/terrain, vegetation (LOD1 nationwide with [LOD2–3 tropical tree research](https://isprs-archives.copernicus.org/articles/XLII-4-W10/55/2018/isprs-archives-XLII-4-W10-55-2018.pdf)), water bodies, transportation networks, city furniture, bridges, and tunnels. The [Digital Underground project](https://sec.ethz.ch/research/digital-underground.html) (SLA + Singapore-ETH Centre) extends coverage to subsurface utilities, train lines, and underground infrastructure. Simulation domains include solar irradiance, wind flow, flood modeling, pedestrian simulation, traffic analysis, noise, energy, and [autonomous vehicle testing environments](https://en.wikipedia.org/wiki/Virtual_Singapore).

**Maturity & Adoption (5/5):** Virtual Singapore was [launched December 3, 2014 and completed its R&D phase in 2022](https://en.wikipedia.org/wiki/Virtual_Singapore), transitioning to operational status under SLA ownership. The programme received **SGD 73 million** for R&D with an additional [SGD 8 million for 3D national mapping](https://www.nrf.gov.sg/programmes/virtual-singapore). Multiple government agencies actively use the platform including the Housing Development Board (HDB) for [environmental simulations in town planning](https://www.hdb.gov.sg/about-us/hdbs-refreshed-roadmap-designing-for-life/tengah-showpiece/environmental-simulations), the Public Utilities Board (PUB) for flood management, and the Civil Aviation Authority for flight safety. SLA launched a [second nationwide data capture in 2019](https://venturebeat.com/technology/how-singapore-created-the-first-country-scale-digital-twin) to update the model, and OneMap3D continues active development as the public-facing platform.

**Integration Posture (2/5):** The core Virtual Singapore platform is accessible only to authorized government agencies and approved entities, with no public API to the full platform. The [OneMap3D Developer Programme](https://www.geoworks.sg/onemap3d-developer-programme) provides limited public access through 3DTiles APIs, CityGML v2 building model downloads, and a 3D Singapore Sandbox for startups and developers. Property portals like Mogul.sg and PropNex have integrated OneMap3D data. However, the platform's Dassault 3DEXPERIENCity backbone is a closed commercial system, and integration between the digital twin and external simulation tools requires approved agency access rather than open API composition.

**Governance (2/5):** Governance is split between the [National Research Foundation (NRF, under the Prime Minister's Office) for development and SLA for data and operations](https://www.nrf.gov.sg/programmes/virtual-singapore), with [GovTech providing ICT expertise](https://www.nrf.gov.sg/programmes/virtual-singapore). Other participating agencies include URA (Urban Redevelopment Authority), HDB, PUB, and CAAS, each contributing domain data and use cases. The roadmap is entirely government-controlled with no external community contribution mechanism. Funding comes from Singapore's national budget through NRF allocations and agency co-funding (CAAS and PUB co-funded 50% of the [SGD 8 million 3D mapping initiative](https://geospatialworld.net/prime/case-study/national-mapping/virtual-singapore-building-a-3d-empowered-smart-nation/)).

### Bentley iTwin Platform

**Organization:** Bentley Systems, Incorporated
**Link:** [bentley.com/software/itwin-platform](https://www.bentley.com/software/itwin-platform/)
**Description:** A cloud-native platform of APIs and open-source libraries for creating digital twins of infrastructure assets, integrating BIM, reality data, GIS, and IoT sensor streams with version-controlled change tracking. The iTwin.js client libraries are MIT-licensed open source while cloud services (synchronization, visualization streaming, change tracking) are commercial.
**Type:** Open-core commercial platform
**License:** Open-core — iTwin.js is MIT; cloud services are proprietary/commercial

#### Dimension Analysis

**Technical Architecture (4/5):** The iTwin Platform follows a modular, cloud-native architecture built on Azure, with the central [iTwin entity connecting multiple data repositories](https://developer.bentley.com/itwin-platform-concepts/) including design data, reality models, IoT sensors, and ML analytics. The **iModel** format functions as a version-controlled repository for engineering data, standardized via Base Infrastructure Schemas (BIS) and built on SQLite. The [iTwin.js monorepo](https://github.com/iTwin/itwinjs-core) contains cross-platform TypeScript libraries for frontend (WebGL visualization), backend (iModel access), geometry, markup, and extension frameworks. The [developer portal](https://developer.bentley.com/apis/) exposes a comprehensive REST API surface organized into Administration, Digital Twin Management, Reality Capture, Reporting, Synchronization, Validation, and Visualization groups — all over HTTPS with OAuth 2.0 authentication. Bentley's 2024 [acquisition of Cesium](https://en.wikipedia.org/wiki/Bentley_Systems) added native 3D Tiles (OGC Community Standard) streaming for city-scale geospatial data delivery.

**Openness & Licensing (3/5):** The iTwin.js core library is confirmed **MIT-licensed** from [source file headers and the GitHub repository](https://github.com/iTwin/itwinjs-core) — correcting the discovery baseline which claimed Apache-2.0 (the related [imodel-native repo](https://github.com/iTwin) uses Apache-2.0). The open-source component is substantial: **702 stars**, 236 forks, and active development at **v5.6.1** (February 13, 2026). However, the `@bentley/imodeljs-native` backend module [enforces authentication for non-Snapshot iModels](https://github.com/iTwin/itwinjs-core/blob/master/docs/learning/backend/AccessingIModels.md), meaning synchronized change-tracking — the platform's core commercial value — requires paid Bentley cloud services. The iModel format is proprietary (though SQLite-based), and while Keith Bentley has stated customers can [use iTwin without paying Bentley](https://aecmag.com/digital-twin/bentley-systems-itwin-phase-two/), practical production use of non-static digital twins requires cloud service subscriptions starting at [$199/month](https://developer.bentley.com/pricing/).

**City-Scale Capability (4/5):** The platform has been deployed for city-scale digital twins including [Dublin (emergency response)](https://blog.bentley.com/insights/best-of-2025-6-stories-that-showcase-how-digital-twins-and-ai-are-transforming-infrastructure/), a [digital twin of London](https://digitaltwininsider.com/2024/05/29/bentley-systems-transforming-industries-with-advanced-digital-twin-technologies/), and multiple Singapore deployments across the [Land Transport Authority and PUB water systems](https://techinformed.com/can-ai-and-digital-twins-help-fix-our-cities-crumbling-infrastructure/). Infrastructure coverage is broad: bridges (East 138th Street, NYC; Robert Street, Minnesota), dams (Yuba Water, California), highways ([I-95 Virginia expansion](https://www.smartcitiesdive.com/news/Bentley-Systems-digital-twins-transportation-infrastructure-projects/759534/)), tunnels (Severn Tunnel, UK), and road networks ([Georgia DOT's 80,000+ miles](https://techinformed.com/can-ai-and-digital-twins-help-fix-our-cities-crumbling-infrastructure/)). The platform excels at infrastructure digital twins but lacks native urban planning domains such as zoning, land use, and pedestrian simulation.

**Maturity & Adoption (5/5):** Bentley Systems is a publicly traded company (Nasdaq: BSY) with **$1.35 billion annual revenue** (2024) and [5,200+ employees across 40 countries](https://en.wikipedia.org/wiki/Bentley_Systems). The iTwin.js repository shows **702 stars**, 236 forks, 346 open issues, and [78 recent contributors](https://github.com/iTwin), with the latest release **v5.6.1** on February 13, 2026 and commits through March 29, 2026. Named production deployments span multiple continents including the [New Orleans 17th Canal Pump Station, Severn Tunnel (UK), Jazan City Port (Saudi Arabia), and Manaus flood resilience (Brazil)](https://blog.bentley.com/insights/best-of-2025-6-stories-that-showcase-how-digital-twins-and-ai-are-transforming-infrastructure/). The platform serves as the backbone for Bentley's entire digital twin strategy, with continuous investment in new capabilities like [iTwin Engage (Unreal Engine integration)](https://blog.bentley.com/insights/step-inside-the-future-bentley-unveils-itwin-engage-turning-infrastructure-plans-into-immersive-experiences/) and SYNCHRO+ for AI-driven 4D construction simulation.

**Integration Posture (4/5):** The [developer portal](https://developer.bentley.com/apis/) exposes over **30 REST API groups** covering iModels, visualization, reality capture, reporting, sensor data, clash detection, synchronization, carbon calculation, and webhooks — all with OpenAPI documentation and OAuth 2.0 authentication. The platform includes connectors for ingesting data from MicroStation, Revit, Aveva, and other design tools into the iModel format. Bentley is a [multinational member of buildingSMART International](https://www.buildingsmart.org/bentley-systems-joins-as-a-multinational-member-announces-support-of-ifc-for-digital-twins/) with IFC import/export support, and the Cesium acquisition provides native 3D Tiles and integration with Google Photorealistic 3D Tiles. No native CityGML support was found, which is a notable gap for OGC-standard urban data exchange.

**Governance (2/5):** The platform is controlled entirely by **Bentley Systems, Incorporated**, a public company led by CEO Nicholas Cumins (since July 2024, the [first non-family CEO](https://en.wikipedia.org/wiki/Bentley_Systems)). Seequent is a wholly-owned subsidiary of Bentley (acquired 2021 for $1.05 billion) focused on geosciences — it does not control the iTwin Platform. Community contribution to iTwin.js requires a [Contributor License Agreement (CLA)](https://github.com/iTwin/itwinjs-core) and follows a standard pull request review process, but the commercial roadmap, cloud service pricing, and platform strategy are set by Bentley corporate without external community governance. Funding is from Bentley's commercial operations and public market capitalization.

### Esri ArcGIS Urban

**Organization:** Esri, Inc.
**Link:** [esri.com/en-us/arcgis/products/arcgis-urban/overview](https://www.esri.com/en-us/arcgis/products/arcgis-urban/overview)
**Description:** A web-based 3D application for urban planning, zoning management, scenario analysis, and community engagement that generates schematic digital twins from OpenStreetMap data without requiring pre-existing 3D models. Tightly integrated with the ArcGIS ecosystem for data, analytics, and visualization.
**Type:** Proprietary commercial SaaS/Enterprise application
**License:** Proprietary — requires ArcGIS Online or ArcGIS Enterprise subscription with Urban license

#### Dimension Analysis

**Technical Architecture (3/5):** ArcGIS Urban is a web-based application built on Esri's proprietary ArcGIS platform, using [hosted feature layers as its backend storage](https://doc.arcgis.com/en/urban/latest/get-started/get-started-setting-up.htm) with a hierarchical data model covering Urban Models, Plans, Projects, Scenarios, Parcels, and Zoning types. The platform exposes a [public GraphQL API](https://developers.arcgis.com/arcgis-urban-api/) (not REST) for programmatic CRUD operations, authenticated via ArcGIS Online OAuth 2.0. Visualization uses WebGL rendering through the ArcGIS Maps SDK for JavaScript with **I3S (Indexed 3D Scene Layers)**, Esri's own 3D standard now an [OGC Community Standard](https://www.esri.com/arcgis-blog/products/arcgis/3d-gis/citygmlbuildingstoi3s). The architecture is tightly coupled to the ArcGIS ecosystem — all data flows through Esri's geodatabase infrastructure, and while [OGC WFS, WMS, and OGC API Features are supported at the platform level](https://enterprise.arcgis.com/en/server/latest/publish-services/linux/ogc-support-in-arcgis-server.htm), ArcGIS Urban's own data model is proprietary.

**Openness & Licensing (1/5):** ArcGIS Urban is **fully proprietary and closed-source** with no open-source component. Usage requires an [ArcGIS Online account with an Urban license assigned](https://doc.arcgis.com/en/urban/latest/get-started/get-started-setting-up.htm), or as of May 2024, an [ArcGIS Enterprise 11.3 deployment](https://www.esri.com/arcgis-blog/products/urban/design-planning/introducing-arcgis-urban-on-arcgis-enterprise). The GraphQL API is publicly documented but requires authenticated ArcGIS credentials. CityGML data can be imported only through [external conversion tools](https://www.esri.com/arcgis-blog/products/arcgis-pro/3d-gis/import3dcitydatainarcgis) (Esri Data Interoperability Extension + FME or con terra tools), not natively. Exact pricing is not publicly listed and requires contacting Esri sales, though a free trial is available.

**City-Scale Capability (4/5):** ArcGIS Urban provides strong coverage of core urban planning domains: [zoning management, land use planning, 3D scenario evaluation, development pipeline management, project review, and community engagement](https://www.esri.com/en-us/arcgis/products/arcgis-urban/overview) with automatic schematic 3D building and tree generation from OpenStreetMap data. Built-in indicators track projected changes in population, jobs, households, and energy use. The application can cover entire cities and regions — Boston is provided as an [example city demonstrating full-scale capabilities](https://doc.arcgis.com/en/urban/latest/get-started/get-started-example-city.htm). However, coverage gaps exist in transportation simulation, environmental analysis (Esri staff [confirmed wind and solar radiation analysis are not available in Urban](https://community.esri.com/t5/arcgis-urban-questions/can-you-conduct-a-wind-and-sun-shade-analysis-at/td-p/1505445)), and infrastructure lifecycle management, which require separate ArcGIS products.

**Maturity & Adoption (5/5):** ArcGIS Urban reached general availability on [July 1, 2019](https://en.wikipedia.org/wiki/ArcGIS) and releases approximately **three times per year**, with the most recent release in November 2025 per the [API release notes](https://developers.arcgis.com/arcgis-urban-api/). On-premises deployment was added with [ArcGIS Enterprise 11.3 in May 2024](https://www.esri.com/arcgis-blog/products/urban/design-planning/introducing-arcgis-urban-on-arcgis-enterprise). Named city deployments include [aspern Seestadt, Vienna](https://www.esri.com/about/newsroom/blog/vienna-seestadt-smart-city-prototyping/) (Europe's largest urban development), [Mesa, Arizona](https://www.esri.com/en-us/lg/industry/government/stories/city-of-mesa-revolutionizes-urban-planning-projects-with-gis) (transit-oriented development), [Littleton, Colorado](https://www.viewprogis.com/arcgis-urban-deployment) (zoning update), and planning use cases in Seattle, Honolulu, and Charlotte documented in an [academic assessment](https://link.springer.com/article/10.1007/s43762-021-00016-9). The product benefits from Esri's global install base and enterprise support infrastructure.

**Integration Posture (3/5):** The [ArcGIS Urban GraphQL API](https://developers.arcgis.com/arcgis-urban-api/) enables programmatic access for CRUD operations, workflow automation, and product integrations, with an interactive GraphiQL explorer and Python support via the sgqlc client library. Within the ArcGIS ecosystem, Urban integrates with CityEngine for detailed 3D design, ArcGIS Pro for advanced analysis, Living Atlas for demographic data, ArcGIS Hub for community engagement, and [Experience Builder and StoryMaps for presentation](https://www.esri.com/en-us/arcgis/products/arcgis-urban/overview). CityGML import is supported through the ArcGIS Pro [Data Interoperability Extension with FME](https://www.esri.com/arcgis-blog/products/arcgis-pro/3d-gis/import3dcitydatainarcgis), and the broader platform supports OGC WFS/WMS/WMTS. However, integration outside the Esri ecosystem remains friction-heavy, requiring ArcGIS authentication for all API access.

**Governance (1/5):** ArcGIS Urban is developed and controlled entirely by **Esri, Inc.** (Redlands, California), specifically by the [Esri R&D Center Zurich](https://en.wikipedia.org/wiki/ArcGIS) (formerly Procedural Inc., creators of CityEngine). There is no community contribution model, open governance structure, or external steering committee. Users can submit feature requests through [Esri Community forums](https://community.esri.com/t5/arcgis-urban/ct-p/arcgis-urban), but the product roadmap is set entirely by Esri. Pricing follows Esri's named-user licensing model, available as an add-on to ArcGIS subscriptions with discounts for local governments through Local Government Agreements.
